# مدير الفواتير والوصولات (Invoice Manager)

برنامج محلي بصيغة HTML لإصدار فواتير المبيعات ووصولات القبض بتصاميم ومقاسات مختلفة (A4 و A5).
يعمل بدون إنترنت، ويحفظ كل شيء كملفات داخل مجلد تختاره على جهازك.

## التشغيل

1. افتح `index.html` باستخدام **Google Chrome** أو **Microsoft Edge** (المتصفحات الأخرى لا تدعم الحفظ داخل مجلد).
2. أول مرة، اضغط **اختيار مجلد العمل** واختر مجلداً فارغاً، مثلاً `Documents/الفواتير`.
3. في المرات التالية، اضغط **متابعة العمل**، لأن المتصفح يطلب تأكيد الإذن في كل مرة.

لنقل العمل إلى جهاز آخر: انسخ مجلد البرنامج ومجلد العمل، ثم اختر نفس مجلد العمل على الجهاز الجديد. الترقيم يكمل من حيث توقف.

## الاستخدام اليومي

- **إصدار مستند:** اختر النوع والقالب والمقاس، عبّئ البيانات، والمعاينة تتحدث مباشرة. الرقم يُعطى تلقائياً عند الحفظ (أو اكتب رقماً يدوياً).
- اختصارات: `Ctrl+S` حفظ، `Ctrl+P` طباعة، و `Enter` في آخر سطر مواد يضيف سطراً جديداً.
- البرنامج يتذكر طريقة الدفع والشروط واسم المحاسب من آخر مستند لكل نوع.
- **لوحة التحكم:** المبيعات والمقبوض ونسبة التحصيل (هذا الشهر / هذه السنة / الكل)، آخر المستندات، وأكثر الزبائن ديناً.
- **الأرشيف:** بحث بالاسم أو الرقم أو التاريخ، فلترة حسب الحالة (مدفوعة / جزئية / آجل)، ومنه: فتح للتعديل، طباعة، تكرار كمستند جديد، حذف.
- **التسديدات:** كل وصل قبض يمكن ربطه بفاتورة. زر «💵 تسديد» على أي فاتورة عليها متبقي يفتح وصلاً جاهزاً بالمبلغ المتبقي واسم الزبون ورقم الفاتورة، ومن نموذج الوصل تختار الفاتورة من قائمة فواتير الزبون المفتوحة. المتبقي على الفاتورة = الصافي − الواصل المكتوب بالفاتورة − وصولات التسديد المرتبطة. تبويب «التسديدات» يعرض أرشيف الوصولات مع فاتورة كل وصل والمتبقي عليها، وتسديدات أي فاتورة لوحدها، والفواتير اللي عليها مبالغ. الربط يُحفظ في الوصل (`data.invoiceNo` = رقم الفاتورة).
- **العملاء:** يُجمعون تلقائياً من المستندات. لكل زبون: المشتريات، المقبوض (الواصل + وصولات القبض)، والمتبقي عليه. زر «وصل قبض» يعبّي اسمه والمبلغ المتبقي.
- **الوضع الليلي:** زر 🌙 أعلى الشاشة، ويتذكره البرنامج.

## تسجيل الدخول والحفظ على Firebase

البرنامج يفتح بشاشة دخول. الحساب على **Firebase Authentication** (بريد + كلمة سر)، ونفس الحساب يعمل على كل الأجهزة.
كل البيانات تُحفظ في **Firestore** تحت حسابك: بيانات الجهة، القالب المختار وألوانه، الترقيم، وكل الفواتير والوصولات.

- **الحاسبة:** اختر مجلد عمل كالمعتاد. كل حفظ يُرفع تلقائياً، وتغييرات الأجهزة الأخرى تنزل للمجلد (كل دقيقة وعند الرجوع للنافذة). المجلد يبقى نسخة احتياطية تعمل بدون إنترنت.
- **الهاتف أو جهاز بدون مجلد:** يعمل من Firebase مباشرة.
- أول مزامنة لمجلد فيه بيانات تدمج الطرفين (اللي بالمجلد يُرفع، واللي بـ Firebase ينزل).
- الحذف يُحفظ كعلامة حتى يُحذف من الأجهزة الأخرى.

### الأمان

- كلمة السر يتحقق منها Firebase، ولا تُحفظ على الجهاز أبداً.
- قواعد Firestore تسمح لكل حساب بمساحته فقط (`users/{uid}`)، فحتى مع معرفة إعدادات المشروع محد يقرأ بياناتك.
- جلسة الدخول على الجهاز مشفّرة بـ AES-256-GCM بمفتاح مشتق من كلمة السر (PBKDF2-SHA256، 600,000 دورة). هذا يسمح بالدخول بدون إنترنت بنفس كلمة السر.
- كلمة السر لازم تكون قوية: 10 أحرف أو أكثر، ومن 3 أنواع على الأقل.
- بعد 5 محاولات خاطئة يتوقف الدخول مؤقتاً، من 30 ثانية حتى 15 دقيقة. Firebase أيضاً يوقف المحاولات الكثيرة.
- قفل تلقائي بعد الخمول (5 / 15 / 30 / 60 دقيقة)، وزر 🔒 للقفل الفوري.
- نسيان كلمة السر: Firebase يرسل رابط تعيين إلى البريد. تغيير كلمة السر من الإعدادات.
- سياسة أمان المحتوى (CSP) تسمح بتشغيل ملفات البرنامج فقط، وتسمح بالاتصال بـ Firebase (و api.github.com لنقل البيانات القديمة) فقط.

ملاحظة: ملفات مجلد العمل على الحاسبة نفسها غير مشفّرة، ويحميها حساب ويندوز.

### تجهيز Firebase أول مرة

1. أنشئ مشروعاً من `console.firebase.google.com` (الخطة المجانية Spark تكفي).
2. **Authentication** ← فعّل **Email/Password**.
3. **Firestore Database** ← Create database (Production mode).
4. الصق القواعد في Firestore ← Rules:

```
rules_version = '2';
service cloud.firestore {
  match /databases/{db}/documents {
    match /users/{uid}/{doc=**} {
      allow read, write: if request.auth != null && request.auth.uid == uid;
    }
  }
}
```

5. Project settings ← Your apps ← Web app: انسخ `apiKey` و`projectId`. تضعهما في `app/firebase-config.js` (فلا يُطلبان على أي جهاز)، أو تدخلهما بشاشة البرنامج أول مرة على كل جهاز. هذه القيم ليست سرية.
6. أنشئ حسابك من البرنامج («إنشاء حساب»). بعدها ألغِ التسجيل الجديد من Authentication ← Settings ← User actions ← **Enable create (sign-up)**.

### نقل البيانات من GitHub

إذا كنت تحفظ سابقاً على مستودع GitHub خاص، استخدم **الإعدادات ← نقل بياناتك من مستودع GitHub القديم**: أدخل المستودع والرمز مرة واحدة، وتنتقل كل الملفات إلى Firebase.

## النشر على GitHub Pages

الملف `.github/workflows/pages.yml` ينشر البرنامج عند كل دمج في `main`، فيفتح من رابط بدل الملف.
فعّله مرة واحدة من Settings ← Pages ← Source: **GitHub Actions**.
(البيانات لا تكون بمستودع البرنامج، فهي في Firebase ومجلد العمل.)

## ترتيب مجلد العمل

```
workspace.json                         علامة المجلد
settings/settings.json                 بيانات الجهة، الشعار، العملة، المقاس، بادئات الترقيم
settings/counters.json                 آخر رقم صادر لكل نوع مستند
templates/<id>.json                    القوالب المضافة
documents/<type>/<year>/<type>-00001.json   المستندات الصادرة
audit/<YYYY-MM>/<time>-<id>.json       سجل العمليات (ملف لكل عملية، يُرفع لـ Firebase)
backups/before-v2-<date>.json          نسخة تلقائية قبل ترحيل البيانات (على الحاسبة فقط)
```

نسخة البيانات الحالية **2**. الترحيل من النسخة 1 غير هدّام: يأخذ نسخة كاملة أولاً، ولا يعيد كتابة أي مستند؛ الحقول الجديدة كلها اختيارية والمستندات القديمة تُقرأ كما هي.

## القوالب والمقاسات

| | A4 / Letter | A5 | حراري 80 / 58 ملم |
|---|---|---|---|
| فاتورة مبيعات | صفحة كاملة عمودية | نفس التصميم مصغّر على A5 عمودي | قالب "وصل كاشير"، طول الورقة حسب المحتوى |
| وصل قبض | وصلين بالورقة (أصل + نسخة) مع خط قص | وصل واحد على A5 أفقي | قالب "وصل كاشير" |

كل قالب يدعم: نموذج فارغ للكتابة اليدوية، علامة مائية من الشعار، وألوان قابلة للتعديل (أو ألوان جاهزة بضغطة) تُحفظ في الإعدادات.

### التصميم والطباعة (تبويب القوالب)
يطبَّق على كل المستندات والمعاينة تتغير مباشرة: الخط (Cairo، Readex Pro، Tahoma، نسخ)، حجم المحتوى 85–120%، حجم الشعار، هوامش الورقة، شكل الجدول (حدود كاملة، أسطر ملونة، خطوط أفقية)، أعمدة جدول المواد (الرمز، الوحدة، الملاحظات)، مكان التوقيعات والختم، ورسالة أسفل المستند.

## الحسابات
محرك واحد (`Render.totals`) يُستخدم في المحرر والمعاينة والطباعة والأرشيف والعملاء ولوحة التحكم، ويحسب بأعداد صحيحة (1/10000) حتى لا تظهر أخطاء الكسور:

```
سطر المادة = الكمية × السعر
المجموع    = مجموع الأسطر
المتبقي    = المجموع + الرصيد السابق − المدفوع
```

الفواتير لا تعرض خصماً ولا أجوراً ولا ضريبة ولا "صافي" (بطلب من صاحب البرنامج). الفواتير القديمة التي فيها خصم محفوظ تبقى حساباتها صحيحة: يظهر المجموع بعد الخصم.

- **الدفع بأكثر من طريقة**: أسطر دفع (نقداً، تحويل، بطاقة، صك...) مع رقم مرجع. فارغ = مدفوعة بالكامل، 0 = آجل. طرق الدفع تُعدَّل من الإعدادات.
- **تاريخ الاستحقاق**: الفاتورة غير المسددة بعده تظهر "متأخرة".
- **الإلغاء بدل الحذف**: المستند الملغى يبقى بالأرشيف بسببه ولا يدخل بأي حساب، ويمكن إرجاعه.
- **الوصل** يمكن ربطه بأكثر من فاتورة (`data.allocations`)، ولا يُحتسب على الفاتورة أكثر من المتبقي عليها؛ الزيادة تبقى رصيداً للزبون. تنبيه عند حفظ وصل مكرر (نفس الزبون والمبلغ والتاريخ).
- **سجل العمليات**: كل إنشاء وتعديل وإلغاء وحذف وتغيير إعدادات مع الوقت والحساب والقيم السابقة. المستند المحذوف يُرجع من السجل.
